# BG Company 2.0 서버 연결 준비

확인일: 2026-10-11. 서버 설치·연결·운영 변경을 완료한 문서가 아니라, 확보된 접근과 다음 연결 절차를 기록한다.

## 확인된 접근과 차단

| 항목 | 판정 | 근거 |
|---|---|---|
| GitHub 개발 브랜치 | 연결됨 | 연결된 GitHub 도구로 개발 브랜치 조회 성공 |
| 현재 Work에서 VPS SSH | 접속 불가 | 기존에 알려진 주소에 SSH 재시도, `Network is unreachable` |
| 현재 Work SSH 인증 | 미설정 | SSH 디렉터리의 일반 파일 0개, 서버 연결 환경변수 없음 |
| 기존 Hostinger VPS 연결 도구 | 이번 검색에서 찾지 못함 | Hostinger Mail과 새 DigitalOcean 서버 생성 연결은 기존 VPS 관리에 맞지 않음 |
| 보유 서버컴 | 사용자 보유 확인, 접속 미확인 | OS·가동 상태·네트워크·로그인 연결 정보 없음 |
| Work Cloud의 로컬 컴퓨터 접근 | 계정 지원 여부 미확인 | 공식 기능은 있지만 계정·워크스페이스·출시 상태에 따라 제공 |

SSH 도달 실패만으로 VPS 장애를 판정하지 않는다. 서버컴이 연결됐거나 VPS 운영을 변경했다고 주장하지 않는다.

## 목표 역할

- Hostinger VPS: 기존 BG Company, 서비스와 PostgreSQL, 예약 작업을 유지한다. 실제 자원 조사를 먼저 수행한다.
- 여기 Work: 조사·설계·코드·검증을 진행하고 결과를 Git에 남긴다.
- 보유 서버컴: VPS 자원이 부족하거나 지속 실행이 필요할 때 개발·빌드·테스트 Worker를 추가한다. 우선 기존 OS와 데이터를 보존한다.

서버컴의 GPU는 GPT/Codex 기반 개발의 필수 조건이 아니다. 이번 단계에서 로컬 LLM 설치, GPU 업그레이드, 새 유료 서버 구매를 요구하지 않는다.

## 첫 연결 순서

1. 서버컴의 현재 OS, 인터넷 연결, 기존 용도와 데이터 보존 여부를 확인한다.
2. Windows 또는 macOS 데스크톱을 사용하는 경우 최신 ChatGPT 데스크톱 앱과 같은 계정의 접속 상태를 확인한다. 로그인은 공식 앱에서 사용자가 직접 한다.
3. 계정에서 Work Cloud의 로컬 컴퓨터 접근을 제공하는지 확인한다. 지원되는 경우에만 해당 컴퓨터와 허용할 작업 폴더를 연결하고 새 Cloud 작업을 시작한다. 기존 웹 대화에 자동으로 접근이 추가되는 것으로 취급하지 않는다.
4. 해당 기능이 없는 경우에는 서버컴에서 로컬 Codex를 실행하고 Git을 통해 이 Work의 개발 결과를 이어받는 경로를 검증한다. 이 경로도 현재 웹 대화의 직접 서버 제어와 동일하지 않다. Linux 서버는 SSH·CLI 경로를 별도로 정한다.
5. 실제 연결 뒤 OS, CPU·메모리·디스크, 저장소와 도구 버전을 읽기 전용으로 확인한다. 이어서 서버컴에서 VPS까지의 네트워크 도달 여부와 기존 SSH 인증을 확인한다.
6. 서버에 있는 기존 저장소 경로를 확인한 뒤 `scripts/bg-v2-audit.py`로 VPS를 조사한다. 환경변수·로그·DB 행 원문을 출력하거나 seed를 실행하지 않는다.
7. 검증된 자원과 접근을 기준으로 격리된 작업 공간과 Worker를 준비한다. 재부팅·실패·사용량 부족 이후 복구와 실제 프로세스 종료 확인까지 검증한 뒤 지속 실행을 선언한다.

로컬 파일과 도구를 사용하는 동안 서버컴은 전원·네트워크·앱 연결을 유지해야 한다. 새 SSH 키 등록, Docker 권한, 방화벽·공유기 설정 등 권한 변경이 필요한 경우 구체적인 범위를 먼저 검토한다. 첫 조사에 관리자 권한 전체를 자동 부여하지 않는다.

## 인증과 승인

비밀번호·개인키·쿠키·Codex 인증 파일을 대화, 보고서 또는 Git에 붙여 넣지 않는다. 앱 로그인과 보안 연결의 인증 화면을 사용한다. SSH 호스트 키는 확인된 값으로 검증하며 확인을 끄는 방식으로 연결하지 않는다.

사용자가 승인한 범위는 안전한 조사·개발·격리 테스트와 연결 준비다. 운영 공개, 결제 활성화, 유료 구매와 고위험 권한 변경은 실제 변경·검증·롤백 계획이 준비된 뒤 별도 승인받는다.

## 공식 문서

- [Work 시작과 기기 간 연속 작업](https://learn.chatgpt.com/docs/get-started-with-work): 로컬 접근을 켠 뒤 새 작업을 시작해야 하며, 기존 작업의 실행 방식은 유지된다.
- [Work Cloud와 dots의 로컬 컴퓨터 접근](https://learn.chatgpt.com/docs/enterprise/cloud-local-access): 지원 여부, 연결된 컴퓨터와 앱의 가동 조건, 계정 로그인과 관리자 설정을 설명한다. 이 문서만으로 개인 계정의 지원을 확정하지 않는다.
- [원격 연결](https://learn.chatgpt.com/docs/remote-connections): 데스크톱 호스트·모바일 원격 접근·SSH 작업 공간은 서로 다른 연결 경로다.
- [OpenSSH 연결 설정](https://man.openbsd.org/ssh_config): 호스트 키 확인과 인증·포워딩 설정의 기준.

현재 필요한 다음 정보는 서버컴의 운영체제다. OS와 실제 제공되는 기능을 확인하기 전에는 설치 명령이나 디스크 변경을 실행하지 않는다.
