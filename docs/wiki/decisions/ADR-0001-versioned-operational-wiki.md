# 버전 관리되는 운영 위키를 조직 기억으로 사용

## 배경

BG Company에는 기능별 설계 문서, 운영 Runbook, Agent 역할 문서가 있지만 실패 원인과 예방 규칙을 한곳에서 추적하는 입구가 없었다. 실행 중 QA 피드백은 같은 파이프라인 안에서 반영되지만, 다음 실행과 다음 개발 작업까지 이어지는 장기 기억은 사람이 코드와 문서를 찾아 연결해야 했다.

## 결정

- `docs/wiki`를 BG Company의 운영 위키로 사용한다.
- 실패는 고유 `fingerprint`로 식별하고 같은 원인의 재발은 하나의 교훈에 누적한다.
- 교훈은 근본 원인, 안전 복구, 예방 규칙, 회귀 테스트가 연결되어야 완료된 것으로 본다.
- 역할·권한·실행 모드의 현재 불일치는 Agent 운영 지도에서 공개적으로 관리한다.
- 위키 구조와 링크는 저장소 검증 명령으로 확인한다.
- 비밀키, 로그인 정보, 개인정보는 위키에 저장하지 않는다.

## 결과

장점:

- 코드 변경과 교훈이 같은 버전 기록에 남는다.
- 반복 실패를 원인 단위로 집계할 수 있다.
- 새 Agent나 사람이 과거 결정과 안전 경계를 빠르게 찾을 수 있다.

비용과 한계:

- 담당자가 상태와 재발 횟수를 실제로 갱신해야 한다.
- Markdown 위키만으로 운영 이벤트가 자동 학습되지는 않는다.
- 실행 데이터와 문서가 어긋나지 않도록 주간 검토가 필요하다.

## 후속 작업

- Agent 정의의 단일 registry를 도입하고 위키 표를 자동 생성한다.
- 운영 이벤트의 오류 코드를 `fingerprint`와 연결하는 학습 원장을 구현한다.
- 7일 내 반복 실패와 회귀 테스트 누락을 관제 화면에 표시한다.
- 공식 전체 테스트 명령에 위키 검증을 포함한다.

관련 기준은 [위키 홈](../README.md)과 [운영 규칙](../governance.md)을 따른다.
